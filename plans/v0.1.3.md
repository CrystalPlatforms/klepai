# PRD — Klepai v0.1.3 (Brainstorm mode)

**Status:** active PRD for v0.1.3, written ahead of implementation — "na zapas", like v0.1.1 and v0.1.2 (decided 2026-10-29 in a discovery session with the owner). Implementation order stays v0.0.2 → v0.1.0 → v0.1.1 → v0.1.2 → v0.1.3; this document pins the design early.
**Source of truth:** `plans/prd-post-alpha.md` is the master roadmap; on conflict, the master wins. Story 47 lives in the master (reworded this session); stories 57–61 were added there; this document pins down all decided details.
**Predecessor:** v0.1.2 (Unrestricted mode, `plans/v0.1.2.md`) ships before this version.

---

## Problem Statement

An idea does not produce work by itself. Turning "I want feature X" into a PRD, a phased plan, issues, tested code, and a pushed commit is a multi-step ritual the user must drive by hand — today it lives outside Klepai, in a separate agent CLI, run command by command in the right order. Nothing in the app carries the idea from "wouldn't it be nice" to "done".

## Solution

A fourth conversation mode — **Brainstorm** — beside Natural, Agent, and Unrestricted. Brainstorm extends Agent mode with a **bundled planning pipeline**: the agent interviews the user about the idea (Ask), writes a PRD (Blueprint), carves it into a phased plan (Carve), creates issues (Dispatch — GitHub issues via `gh` when the project has git+gh, otherwise local files under `plans/issues/`), implements them tests-first (TDD), and finally proposes **Ship** (lint + type-check + commit + push + close the gh issue). The composer mode button shows the current phase — `Brainstorm: Ask` … `Brainstorm: Ship`.

## User Stories

- **47** *(master, amended)* — as the user, I want a **Brainstorm** mode — an extension of Agent mode — in which the agent runs the bundled planning pipeline on my idea, phase by phase with my confirmation: discovery interview → PRD → implementation plan → issues → tests-first TDD → Ship proposal, so that an idea becomes dev-ready work inside one conversation.
- **57** *(master)* — phase label: the composer mode button and the Details pill read **"Brainstorm: Ask / Blueprint / Carve / Dispatch / TDD / Ship"** as the pipeline advances — plain **"Brainstorm"** before it starts — **in blue** where Agent would be yellow.
- **58** *(master)* — the whole pipeline ships **bundled with Klepai**: its skills are always available in Brainstorm mode, on every machine and brain, regardless of the user's skill settings.
- **59** *(master)* — issues land where the project lives: **GitHub issues via `gh`** when the project has git + gh; **local files under `plans/issues/`** when it does not.
- **60** *(master)* — the TDD phase implements the issues **one by one, tests before code**, and **never commits or pushes on its own**.
- **61** *(master)* — a **Ship proposal** comes once, after all issues are implemented; on acceptance the agent runs lint + type-check + commit + push and **closes the gh issue** — no tag, no release.

## Implementation Decisions

### Mode model (story 47)

- Fourth value on the conversation's mode field beside `natural`, `agent`, `unrestricted`; stored on the conversation row — **survives a restart**, new conversations still start Natural (Q22).
- Brainstorm **extends Agent**: same project-folder requirement, same affordances (file suggestions, attachments, skills), same **permission gates** — it asks exactly where Agent asks (Q23). No interplay with Unrestricted: one mode value, no combination.
- Works on **every brain** — built-in server agent and CLI agents (Claude Code, Codex) alike; the pipeline runs inside that brain's conversation (Q21). Scope is per conversation only — no Settings toggle.

### Pipeline flow (stories 47, 60, 61)

- Phases in order: **Ask → Blueprint → Carve → Dispatch → TDD → Ship**. The Ship phase starts as a **proposal** at the end of TDD; the label switches to `Brainstorm: Ship` only when the user accepts (Q35 = 1).
- The user writes an idea in a Brainstorm conversation and the agent **starts the pipeline by itself** — the first discovery questions come unprompted, no command needed (Q15 = 1).
- The agent **stops after every phase** and asks before moving on (Q16 = 1); the discovery phase is an interview by nature.
- **Side questions never derail the pipeline**: the agent answers normally, the phase stays unchanged, and the pipeline resumes when the user says to go on (Q32 = 1).
- One **Ship proposal per pipeline**, after all issues are implemented — not per issue.
- After Ship completes, the label returns to plain **"Brainstorm"**, the conversation behaves like ordinary Agent, and a **new idea starts a fresh pipeline from Ask** (Q28 = 1).

### Bundled skills (story 58; Q18, Q31)

- The pipeline ships as **Klepai skills** in the existing skills system (light index + `read_skill`): an orchestrator skill plus phase skills — ask, blueprint, carve, dispatch, tdd, ship — adapted from the owner's brainstormer plugin and ship/TDD workflows.
- Always present in Brainstorm mode, **regardless of the user's skill settings** — they cannot be switched off inside the mode. Texts in **English**, like the app UI.

### Artifacts (stories 47, 59; Q17, Q19, Q26, Q27, Q34, Q36)

- **Discovery** stays in chat only — no file.
- **Blueprint:** PRD at `plans/prd-<name>.md`; **Carve:** plan at `plans/<name>.md` — flat in `plans/`, like the owner's own plans today.
- **Dispatch is conditional** (Q26): project **with git + gh** → real GitHub issues via `gh`; project **without git/gh** → one file per issue under `plans/issues/`. When gh issues are wanted but the repo is missing, the agent **proposes creating the repo first** (Q19).
- **TDD:** code + tests in the project, issue by issue, **tests written before code** (red-green-refactor); normal Agent permission gates apply; **no commit, no push** — the phase ends on implemented, tested code.
- **Ship:** lint + type-check + commit + push + **close the gh issue** for the done scope — no tag, no GitHub Release (Q34 = 1). Without git the agent **says the folder has no git and skips**; with git but no remote it commits locally, skips the push, and states what it skipped (Q36).
- Without gh issues (local-files dispatch), Ship has no issue to close — it just ships the code.

### Phase label (story 57; Q22, Q24, Q30, Q35)

- Plain **"Brainstorm"** until the pipeline starts (fresh mode, nothing sent); from the first pipeline message the composer button reads **`Brainstorm: <Phase>`**; the Details pill mirrors it.
- Brainstorm renders **in blue** where Agent renders yellow (Unrestricted stays red, from v0.1.2). Blue is the mode's accent only — the v0.1.1 needs-input state (loader squares, sidebar card) is a different element class, not a mode; the owner called the lack of conflict explicitly (Q24).

### Persistence (Q29)

- Mode **and current phase** are stored on the conversation: closing the app mid-Carve and reopening returns to `Brainstorm: Carve` with the agent continuing. Switching to Agent mid-pipeline and back preserves the phase the same way.

## Assumptions

- Ship order stays v0.0.2 → v0.1.0 → v0.1.1 → v0.1.2 → v0.1.3; this PRD was written ahead of all of them by owner decision (Q1 = 1).
- Scope stays exactly the Brainstorm mode — nothing rides along (Q2 = 1, Q25 = 1).
- The bundled phase skills are adaptations of the owner's own workflows (brainstormer plugin: ask/blueprint/carve/dispatch; ship; tdd) — their inner step-by-step rules carry over; only the harness changes (in-app, all brains).
- CLI agents can run the whole pipeline because it is text + project files + `gh`/lint/test commands — nothing needs structured output or app-side parsing beyond what the permission flow already does.
- Needs-input blue (v0.1.1) and Brainstorm blue coexist without confusion — different UI elements (loader/sidebar state vs mode button/pill); owner decision (Q24).
- The Q5–Q14 "multiple directions / pick a card" reading was a misinterpretation and is **void** — replaced by the pipeline design in this session.

## Tradeoffs Considered

- **Model proposes N directions as clickable cards** — explored first in the session and rejected: the owner's intent is the planning pipeline, not answer variants (Q5–Q14 voided).
- **Everything through GitHub, repo required** — rejected: conditional dispatch keeps Brainstorm useful in plain folders without git.
- **Issues always as files and always on GitHub** — rejected: owner chose either/or (files only when git/gh missing, gh issues when present).
- **Full-auto pipeline without phase stops** — rejected (Q16): confirmation gates mirror the proven brainstormer flow and keep the user in control.
- **Brainstorm + Unrestricted combination** — rejected: one mode value; going gate-less stays an explicit, separate choice.
- **Ship creating a tag + GitHub Release** — rejected: that is release-product territory, not /ship; Ship stays commit-and-push sized.

## Validation Strategy (HITL)

1. Switch a project conversation to Brainstorm: the button reads plain "Brainstorm" (blue). Write an idea → the agent starts discovery questions on its own; the label becomes `Brainstorm: Ask`.
2. Answer the interview; the agent summarizes and asks to proceed → accept → label `Brainstorm: Blueprint`; `plans/prd-<name>.md` appears in the project.
3. Proceed → `Brainstorm: Carve`; `plans/<name>.md` appears.
4. Project with git + gh: proceed → `Brainstorm: Dispatch`; real issues appear on GitHub. Project without git: one file per issue lands in `plans/issues/`.
5. Proceed → `Brainstorm: TDD`; the agent implements issue-by-issue with tests before code; **no commit or push happens**; permission gates still ask where Agent would.
6. Mid-TDD, ask something unrelated → the agent answers normally, the label stays `Brainstorm: TDD`, and the pipeline resumes after confirmation.
7. After all issues: the agent proposes Ship while the label still reads `Brainstorm: TDD`; accept → label `Brainstorm: Ship`; lint + type-check + commit + push run (gated like Agent), the gh issue closes, **no tag, no release**.
8. Quit the app mid-Carve → reopen → the conversation is still `Brainstorm: Carve` and the agent continues.
9. Switch the conversation to Agent mid-Ask → switch back → the phase is preserved (`Brainstorm: Ask`).
10. A brand-new conversation starts Natural; the Brainstorm conversation keeps its mode across restart.
11. After Ship: the label is plain "Brainstorm" again; writing a new idea starts a fresh pipeline at Ask.
12. Colors: Brainstorm blue, Agent yellow, Unrestricted red — unchanged elsewhere; the needs-input loader state still shows blue as shipped in v0.1.1.
13. Repeat 1–7 in a Claude Code conversation and a Codex conversation — the same pipeline runs inside those brains.

## Out of Scope (v0.1.3)

- A global Brainstorm toggle in Settings.
- Any Brainstorm + Unrestricted combination.
- Tag / GitHub Release creation in Ship.
- Per-issue shipping (Ship is proposed once, after all issues).
- Editing or re-running a finished pipeline beyond "new idea = fresh pipeline".
- Everything in the master's Out of Scope for the beta line.
