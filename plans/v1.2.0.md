## Problem Statement

Agent mode writes files with `write_file` immediately and silently: there is no review step between the model's edit and the project folder. The user cannot see what a conversation changed — neither what the agent wrote nor how the working tree stands against git — and undoing a bad write means finding and fixing the file by hand. Every coding agent today ships a diff view; Klepai has none.

## Solution

**Klepai Diff** — a read-only diff view living in the existing **`DetailPane`**, behind a **Details | Diff** toggle. Inside Diff, a top switcher picks between two views:

1. **Agent changes** — what this *conversation* wrote through `write_file` and through file-editing `run_command`s, computed from snapshots (before/after), with **per-file revert** as the headline action.
2. **Working tree** — the project folder vs git, the way Claude Code's `/diff` reads it: modified, deleted and untracked files, untracked shown as fully-added new files.

The agent keeps writing without permission gates — Diff is post-fact, not an approval flow.

## Discovery Decisions (owner-confirmed, 2026-11-10)

### Placement and scope (Q1, Q2, Q4, Q6)

- Diff lives in the **existing `DetailPane`** as a **Details | Diff** toggle — no new panel. Inside Diff, a switcher at the top flips between **Agent changes** and **Working tree**.
- **Read-only after the fact** — no accept/reject gate on writes; the agent flow is unchanged (Q2).
- Slot: **v1.2.0**, after Native Menus (v1.1.0); the slot freed when Running Agents was absorbed into the Livebar (see Slot history). Discovered in reserve, built later (Q6).

### Baseline: hybrid git-or-snapshots (Q3)

- Git repo → the Working tree view computes from `git`; non-repo → snapshots carried in SQLite. (What the Working tree tab shows in a non-repo folder is an open question — see below.)

### Snapshots and lifecycle (Q11, Q12, Q13)

- Snapshots are taken **before/after `run_command` too** — but only for commands that edit or create files. Detection runs on the **project index**: a bounded scan at conversation start (size-capped, skipping `.git`, `node_modules`, build output) that keeps hashes + cached contents, then a quick rescan after each command surfaces the changed files with their "before" state. Works without git.
- Snapshots live **with the conversation in SQLite** and are deleted with it. Scope of the Agent changes view is **the current conversation only** (Q7).

### Revert and safety (Q5, Q8)

- **Per-file revert** is the headline action (Q5).
- Before reverting, the current file hash is compared with the hash stored at write time; a mismatch (manual edits after the agent wrote) raises a **warning** before the revert proceeds (Q8).

### Engine and rendering (Q9, Q10)

- Diff is computed in **Rust with the `similar` crate**; the backend returns structured hunks. Syntax highlighting reuses **highlight.js** (already a dependency for code blocks) — no new frontend dependencies.
- Defaults for edges (Q10): binary files → a "binary file changed" notice, no diff; large diffs → first ~500 lines + a "show all" action; new files → the whole file as added lines; deleted files → the whole file as removed lines.

### Working tree details and refresh (Q14, Q15)

- **Untracked files** appear in the Working tree view as new files, as `git status` would (Q14).
- The Diff view **recomputes automatically on tab open/switch** (Q15).

## Draft stories (80–86, finalized at `/blueprint`)

- **80.** *(draft)* As the user, I want a **Details | Diff toggle in the DetailPane**, so that seeing changes never costs the conversation details their home.
- **81.** *(draft)* As the user, I want an **Agent changes view** — files this conversation wrote via `write_file` and file-editing `run_command`s, with a top switcher to flip to Working tree — so the agent's footprint is visible per conversation.
- **82.** *(draft)* As the user, I want a **Working tree view** — the project folder vs git, untracked files shown as new — so I read the whole state of the folder the way `/diff` reads it.
- **83.** *(draft)* As the user, I want **per-file revert** with a **warning when the file changed after the agent's write** (hash comparison), so undoing the agent never silently eats my manual edits.
- **84.** *(draft)* As the user, I want readable diffs — unified hunks, syntax-highlighted, with the binary/large/new/deleted defaults — so review stays fast on any file.
- **85.** *(draft)* As the user, I want the **project index** (bounded scan, rescan after commands) to power `run_command` snapshots, so shell-driven file changes are caught too — even outside git.
- **86.** *(draft)* As the user, I want the Diff view to **recompute on open/switch**, so what I see is current without a manual refresh.

## Open questions (for `/blueprint`)

- **Non-repo folders:** what does the Working tree tab show — a snapshot-driven fallback (agent-touched files only) or a disabled state with a note?
- **Revert of an agent-created file:** is reverting a new file its deletion? Presumably yes — confirm.
- **Deleted-by-command files:** the index carries the "before" content, so a `run_command`-deleted file should diff as full removal — confirm the snapshot covers deletions, not just edits.
- **Paths outside the project folder:** how do `write_file`/`run_command` behave on absolute/escaping paths today, and does Diff snapshot them? (Security-adjacent; may already be handled.)
- **Stale "before" state:** if the user manually edits a file between scans, the index cache holds a stale copy — decide whether the warning (Q8) covers command-snapshots too, or only `write_file` snapshots.

1. Diff is **v1.2.0** — Native Menus (v1.1.0) precedes it. *(First signed as v1.3.0 in this session; re-slotted to v1.2.0 when the owner confirmed Running Agents was absorbed into the v1.0.0 Livebar. The landing roadmap still shows v1.2.0 as Running Agents — fixed when v1.2.0 approaches.)*

3. Two views — Agent changes (current conversation, snapshot-driven) and Working tree (git-driven) — behind a switcher inside the DetailPane.
4. Hybrid baseline: git when present, SQLite snapshots when not.
5. Per-file revert with a hash-mismatch warning; no batch accept/reject (Q5 answered "1", not "3").

7. Edge defaults as listed; untracked = new files; auto-recompute on open.
