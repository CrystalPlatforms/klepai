# PRD — Klepai v0.1.2 (Unrestricted mode)

**Status:** active PRD for v0.1.2, written ahead of implementation (decided 2026-10-29 in a discovery session with the owner). Implementation order stays v0.0.2 → v0.1.0 → v0.1.1 → v0.1.2; this document just pins the design early.
**Source of truth:** `plans/prd-post-alpha.md` is the master roadmap; on conflict, the master wins. Stories 45, 46 and 56 live in the master; this document pins down their decided details.
**Predecessor:** v0.1.1 (agent status notifications, needs-input loader) ships before this version.

---

## Problem Statement

*(carried from the master)* Every action asks for a click the user does not always want to give: a trusted task still stops at every allow dialog — the built-in agent swaps the composer to allow buttons, and CLI agents pause on their own approval prompts. For work the user has already decided to trust, every gate is pure friction.

## Solution

A third conversation mode — **Unrestricted** — beside Natural and Agent. The owner's definition: *"Unrestricted is just Agent without permissions."* In this mode the built-in agent and spawned CLI agents perform everything with zero dialogs: edits, commands, everything auto-accepted. The mode is visibly distinct (red where Agent is yellow), guarded by a warning dialog the first times it is enabled, and behaves otherwise exactly like Agent.

## User Stories

- **45** *(master)* — as the user, I want an **Unrestricted** mode — a third mode beside Natural and Agent — under which the built-in agent and spawned CLI agents perform all actions **without any allow dialog**, so that trusted tasks run hands-free.
- **46** *(master)* — as the user, I want a warning when switching into Unrestricted (it lets the agent do anything without asking), shown on every entry until I check **"don't show again"**, so that the power is conscious but not nagging.
- **56** *(master)* — as the user, I can tell at a glance that a conversation is Unrestricted — the composer mode button and the Details mode pill show it **in red** where Agent would be yellow — so that the no-questions state is never mistaken for ordinary Agent.

## Implementation Decisions

### Mode model (story 45)

- The conversation's mode value gains a third option beside `natural` and `agent`; it is stored on the conversation row exactly like the existing modes — it **survives a restart**, and **new conversations still start Natural** (Q9, Q11).
- Unrestricted carries Agent's semantics minus the permission gates (owner, 2026-10-29): same requirements — the built-in agent works as in Agent; CLI agents need the project folder; every agent affordance (file suggestions, attachments, skills) behaves as in Agent.
- Scope is **per conversation only** — no global toggle in Settings (Q3).

### Switching UX (stories 45, 56)

- **Composer:** the single mode button **cycles** Natural → Agent → Unrestricted → Natural on click; it shows the current mode; **Unrestricted renders in red** in the same spot where Agent renders yellow (Q12, Q13).
- **Details:** a third mode pill **"Unrestricted"** beside Natural and Agent; same pill look, **red accent instead of yellow** when active (Q4, Q8, Q13).
- A mode switch takes effect **from the next message** — CLIs are spawned per message and pick up the new flags then; the running agent is never interrupted (Q14). A permission ask pending from the current run must still be answered manually.
- Switching **away** from Unrestricted never asks anything (Q7).

### Warning gate (story 46)

- **Every** transition into Unrestricted — from the composer cycle or the Details pill, on any conversation — shows a warning dialog, until **"don't show again"** is checked (Q15). The choice persists in local app settings — the only global state this version adds.
- **Cancel** leaves the mode unchanged; disabling the mode never shows anything.
- Exact dialog copy is drafted at implementation and approved by the owner during review.

### Permission behavior in Unrestricted (story 45)

- **Built-in agent:** permission requests are auto-approved before reaching the composer — the composer **never** swaps to the allow buttons in this mode (Q5).
- **CLI agents:** spawned with their **full-bypass** flags — Claude Code skips permissions entirely; Codex bypasses approvals **and the sandbox** (owner's call: zero asks, zero sandbox — Q6).
- Standing Allowed rules (Settings → Allowed) are untouched; in an Unrestricted conversation they are moot, and ordinary Agent conversations keep honoring them (Q5).
- Unrestricted **adds no capabilities** — it only removes confirmation gates (master boundary, reconfirmed Q10, Q16). There is no exception list: no action class asks, ever.

### Interplay with v0.1.1

- In an Unrestricted conversation the permission-driven **needs-input** state (orange loader, notifications) can never fire from permissions — those asks do not exist there. CLI questions asked **in text** and idle notifications are unaffected. (v0.1.1 is not yet implemented; this records the intent for when it lands.)

## Assumptions

- The CLIs' full-bypass flags remain a supported headless surface (both CLIs document these modes today); a flag change upstream is caught at implementation, not in production.
- Full bypass is accepted risk: single-user, local-first app on the owner's own machine; the warning dialog is the conscious-opt-in moment.
- The permission gates live in exactly two places — the built-in agent's ask path and the adapter spawn flags — so bypassing both is complete; no third gate hides elsewhere.
- v0.1.1 will treat "no permission asks" in Unrestricted as "no needs-input from permissions" (intent stated above; its own discovery decides the mechanics).
- v0.1.2 scope stays exactly: the Unrestricted mode — nothing else rides along (Q2).

## Tradeoffs Considered

- **Global Settings toggle (+ per-conversation override)** — rejected: master scope is per-conversation; two surfaces for the same power invite forgetting it is on.
- **Auto-accept with sandbox kept (Codex full-auto)** — rejected: the sandbox still asks to escalate outside its cage, breaking the zero-asks promise; owner chose full bypass.
- **A "never auto-accept" blocklist of catastrophic commands** — rejected: a feature defined as zero gates gets a gate class back; master says Unrestricted adds no capabilities, only removes confirmations.
- **A separate toggle beside the mode picker** — rejected: a third mode value reuses the existing switch UI and storage; a parallel toggle doubles the state to keep in sync.
- **Immediate effect on a pending permission ask** — rejected: mutating gates mid-run is unpredictable; next-message semantics are simple and observable.
- **Resetting to Natural on restart (paranoid default)** — rejected: inconsistent with how Agent persists; owner chose mode persistence like today (Q9).

## Validation Strategy (HITL)

1. Click the composer mode button through the full cycle Natural → Agent → Unrestricted → Natural: the label follows each click; "Unrestricted" renders in red where Agent renders yellow.
2. In Details, three pills appear; "Unrestricted" active shows the red accent, Natural/Agent behave as today.
3. Built-in agent, Unrestricted on: ask it to edit a file **and** run a command → both execute with zero allow buttons; the composer never swaps to allow buttons.
4. Same conversation switched back to Agent → the allow dialogs return for the same kinds of actions.
5. Claude Code conversation, Unrestricted on: file edit + command run with zero prompts.
6. Codex conversation, Unrestricted on: an edit, a command, and an action that would leave the workspace sandbox all run with zero prompts (approvals and sandbox both bypassed).
7. First switch into Unrestricted shows the warning; **Cancel** leaves the mode unchanged; enabling with **"don't show again"** checked → switching away and back shows nothing, and the silence survives an app restart.
8. In an Agent-mode run, with a permission ask pending, switch to Unrestricted → the pending ask still needs a manual answer this run; the **next** message runs with zero asks.
9. Restart the app with an Unrestricted conversation → it is still Unrestricted; a brand-new conversation starts Natural.
10. Settings → Allowed is unchanged; an Unrestricted conversation ignores standing rules while an Agent conversation still honors them.
11. Warning dialog: it appears from **both** entry points (composer cycle and Details pill) until "don't show again" is set — afterwards neither entry point asks.

## Out of Scope (v0.1.2)

- A global Unrestricted toggle in Settings.
- Any exception list / "never auto-accept" blocklist.
- Mid-run gate mutation (pending asks resolved by a mode switch).
- Sandbox-preserving auto-accept for Codex.
- Everything in the master's Out of Scope for the beta line.
