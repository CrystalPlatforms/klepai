# PRD — Klepai v1.0.0 (Klepai Livebar — the system-bar agent panel)

**Status:** active PRD for v1.0.0, written ahead of implementation (decided 2026-11-04 in a discovery session with the owner; pinned early "in reserve", like v0.1.2, v0.1.4, v0.1.5 and v0.1.6 were). Implementation lands after the beta line completes — **1.0.0 = the Livebar + the stability gate**.
**Source of truth:** `plans/prd-post-alpha.md` is the master roadmap; on conflict, the master wins.
**Predecessor:** the whole beta line (v0.1.0–v0.1.9) ships first. The Livebar consumes the agent states (idle / needs input / error) that **v0.1.1** introduces — it has no detection path of its own and cannot ship before v0.1.1 exists.
**Model:** behavior modeled on the **umux Livebar** (stories #177–#184 in the umux repo's `plans/umux-v2.0.0-prd.md`) at the owner's request ("exactly like umux"). Deliberate Klepai extensions beyond the umux spec are marked as such — the lingering Idle/Error rows with the hover trash (story 68) are the one real deviation.
**Master amended by this discovery:** stories 66–70 added; the roadmap gained a **v1.0.0** row; the Versioning bullet and the 1.0.0 gate updated.

## Problem Statement

*(carried from the master, extended by this discovery)* An agent working in the background is invisible: v0.1.1 solves this **inside** the app with notifications and sidebar/loader states. But the information still lives behind the window — seeing who works, who just finished and who waits for permission means switching into Klepai and reading the sidebar. The agent state is already computed; it is just not visible outside the app.

## Solution

**Klepai Livebar** — the Klepai logo in the system bar: the macOS menu bar, the Windows tray beside the clock, the GNOME top bar. A click opens a small panel listing every conversation with a working agent — one row per agent, its state chip and configurable segments — and clicking a row jumps straight to that conversation (opening the Klepai window first if it was closed). Finished and errored agents linger until their conversation is viewed or a per-row hover trash hides them — a deliberate Klepai extension. A **Livebar section in Settings** (on by default) shapes the row: a drag & drop configurator over a seven-segment pool with a live preview. On GNOME the click opens the platform's native menu listing the agents instead — a hard platform limit, not a design choice.

## Implementation Decisions

### Presence and icon (Q5, Q11)

- The icon exists whenever the Klepai app process is running; it is **not** a background mode and not tied to any daemon.
- **Static logo, forever**: no badges, dots, counters or color changes (Q11=1; umux rejected them too). All details live in the panel.
- **macOS**: monochrome template variant (platform convention) — a new template asset joins `app/src-tauri/icons/`. **Windows/Linux**: the colored logo.
- Tauri 2 needs the **`tray-icon` feature** enabled (today `tauri = { version = "2", features = [] }`).

### Click behavior per platform (Q6, Q7, Q9, Q20)

- **macOS**: left-click opens the panel under the icon; right-click opens the small menu — **"Open Klepai" / "Quit Klepai"**.
- **Windows**: the icon sits in the **tray beside the clock** (Q6=1 — the answer to "where on Windows"); left-click opens the panel **above the clock**; right-click the same menu.
- **GNOME**: a click opens the **native menu** — the AppIndicator has no API for opening a window on click, a hard platform limit (umux precedent): one menu item per agent (label from the configured segments; click = jump), plus **"Open Livebar"** opening the panel near the cursor (Wayland positioning best-effort), plus "Open Klepai" / "Quit Klepai". The menu stays **minimal** — no "Hide finished agents" item (Q20=1); lingering rows are cleaned in the panel via the trash.
- **KDE**: behaves like macOS/Windows.

### The panel (Q9, Q19)

- A plain, scrollable list rendered in a **borderless, always-on-top Klepai window** (the v0.1.1 banner pattern) — our own rendering on every platform, so hover, chips, the underline and the trash are identical everywhere; only how the panel is summoned differs per platform.
- One row per conversation with an agent; chip states **Running / Needs input / Idle / Error** (Q19=1); **"No agents running"** empty state; sensible max height with scrolling.
- Popover behavior: closes on outside click or Esc.
- **Live**: rows update as agent states change — a mirror of the same stream the v0.1.1 sidebar states use (**single detection path**, no second one).

### What is listed (Q3)

- Every conversation whose agent is active in this app session — **CLI brains (Claude Code, Codex) and the built-in server agent alike, without distinction** (Q3=1). Model-only chat conversations never appear.
- Needs-input coverage is v0.1.1's exactly: built-in and Claude Code full; **Codex Idle/Error only** until its detector ships — inherited, not reimplemented.

### Lingering rows and the trash (Q4, Q13–Q16) — Klepai extension beyond umux

- umux rows vanish when the agent's process ends; Klepai's **Idle and Error rows linger** until dismissed (Q4=2).
- The trash: a small per-row icon **revealed on hover** (Q13=1); works on **Idle and Error only** (Q14=1) — Running and Needs-input rows cannot be hidden, because they demand attention.
- The trash **never stops an agent** — it only hides the row.
- **Viewing the conversation also drops the row** (Q15=1) — the trash is the manual complement, not the only path.
- The hidden state is **session-only** (Q16=1): nothing persists; a new agent run in the same conversation brings a fresh row back.

### The underline

- The whole row is underlined while its agent **waits for input and the conversation is unviewed**; viewing drops it — the same rule as the v0.1.1 states. Other states never underline.

### Row model (Q10, Q17, Q18)

- Seven segments: **Agent state, Conversation title, Project folder, Agent type, Branch, Worktree, Time running** — umux's Workspace/Tab have no Klepai counterpart.
- Default row: **State | Conversation | Folder**.
- Branch hides itself when the folder is not a git repo; Worktree additionally requires an active collision-guard worktree.
- **Time running freezes at finish/error** (Q17=1) — it shows how long the agent worked, not how long ago.
- Sorting: **newest agent signal on top** (Q18=1).
- Git reads are asynchronous with a cache — never on the hot stream path (the umux 2026-10-20 rule, adopted).

### Jump (Q9)

- Row click → bring the window to front, un-minimize, focus, select the conversation and scroll to it — **the same navigation path as the v0.1.1 notification click** — and clear the underline.
- On macOS with the window closed: the window opens first, then the jump.

### Window close (Q8, Q21)

- **Windows/Linux: X quits** — the app, its agents and the Livebar end together; unchanged from today and from v0.1.1's stance.
- **macOS: X hides the window** (Q21=1) — a deliberate behavior change: app, agents and Livebar keep running; the Dock icon click returns to the window. Implementation: intercept the close request on macOS (prevent + hide) and keep the process alive when the last window closes.
- **No hide-to-tray anywhere** (Q8=1): the Livebar lives with the app window — it is not a background mode (umux rejected it too).

### Settings section (Q12)

- A new **Livebar** tab in `SettingsDialog.tsx`: an on/off switch (**on by default** — the deliberate exception to off-by-default, umux-style), a **drag & drop configurator** (visibility + order), and a **live preview** — one mock-agent row re-rendering on every change; nothing else in the section.
- **One configuration everywhere**: the panel rows and the GNOME menu-item labels come from the same config.

### Boundaries

- No badges or color changes on the icon; no sticky panel; no per-platform row configurations; no grouping of rows by folder.
- The trash does not exist in the GNOME native menu (no hover there) — cleaning happens in the panel (Q20=1).

## Assumptions

- GNOME's AppIndicator offers no API for opening a window on click — menu-first is the platform contract, accepted with umux precedent; Wayland may refuse exact panel positioning, cursor-anchored placement is the accepted best effort.
- The Livebar lists only agents of the **running app process** — a quit app (Win/Linux X) lists nothing; there is no daemon story behind it.
- Needs-input detection is v0.1.1's, with its limits (Codex Idle/Error only at first); the underline follows whatever v0.1.1 detects — **no separate detection path, ever**.
- Agent states come from the app's own pipelines — no screen reading, no process polling.
- macOS keep-alive holds because agents are tokio tasks inside the app process — hidden window, working agents.
- The `tray-icon` feature and **libayatana-appindicator** (Linux) are the only new runtime deps; the Linux CI gains a build dep (umux documents the same for its tray).
- v1.0.0 scope stays exactly: stories 66–70 + the stability gate — nothing rides along.

## Tradeoffs Considered

- **Umux-literal membership (rows vanish at process end)** — rejected (Q4=2): finished agents would be invisible in the panel; lingering + trash is Klepai's own extension.
- **Trash on Running/Needs-input rows** — rejected (Q14=1): agents would work invisibly; attention-demanding rows must not be hideable.
- **Trash-only dismissal (viewing does not drop Idle rows)** — rejected (Q15=1): rows would pile up; viewing is the natural resolve.
- **"Hide finished agents" in the GNOME menu** — rejected (Q20=1): the menu stays minimal; the panel's trash covers cleanup.
- **A badge/dot on the icon for needs-input** — rejected (Q11=1): a static logo; details live in the panel (umux precedent).
- **Hide-to-tray on window close** — rejected (Q8=1): the X behavior stays; the Livebar is not a background mode.
- **macOS X quits (status quo)** — rejected (Q21=1): the Livebar on macOS would die with the window, defeating the feature; umux keeps the app alive.
- **Time running counting past finish** — rejected (Q17=1): "time since finish" is a different metric and misreads as work time; the segment freezes instead.
- **Persisting hidden rows across restarts** — rejected (Q16=1): session-only state; nothing to restore after a quit.

## Validation Strategy

### Automated (Vitest, pure modules)

- **Row model:** the configured segments render in order; disabling drops a segment; reordering persists; a no-git folder hides Branch (no-worktree hides Worktree); Time running freezes at the finish timestamp.
- **One config, two surfaces:** the same configuration produces identical panel rows and GNOME menu-item labels.
- **Lingering:** an Idle/Error row stays after finish; viewing the conversation drops it; the trash removes it without touching the conversation; a new run in a trashed conversation restores a row; Running/Needs-input rows refuse the trash.
- **Underline:** needs-input + unviewed → whole row underlined; viewing drops it; other states never underline.
- **Sorting:** the newest agent signal is on top.
- **States:** all four chips render; Error behaves like Idle (lingers, trashable).

### HITL (owner — macOS first, then Ubuntu/Wayland, then Windows)

1. macOS: the monochrome logo appears in the menu bar while Klepai runs; left-click opens the panel under the icon; right-click shows "Open Klepai" / "Quit Klepai".
2. Run an agent in a conversation → its row appears; let it finish → chip flips to Idle and the row **stays**; hover → the trash appears → trash hides the row; run the agent again in the same conversation → the row returns.
3. Leave an agent waiting on a permission → the whole row underlines; click the row (with the window hidden first) → the window opens, lands on that conversation, the underline drops.
4. Esc / outside click closes the panel; enough agents → the list scrolls; with none → "No agents running".
5. Settings → Livebar: switching off removes the icon; reordering and dropping segments changes the preview and the panel in step; adding Branch in a git project shows it; a no-git folder hides it; switching back on restores the icon.
6. macOS X: close the window → the app stays alive (Dock visible), agents keep working, the Livebar stays, a finishing agent still notifies (v0.1.1); click the Dock icon → the window returns.
7. Ubuntu/GNOME: a click opens the native menu with one item per agent; clicking an item jumps into Klepai; "Open Livebar" opens the panel near the cursor (hover and trash inside); Open/Quit items work.
8. Windows: left-click opens the panel above the clock; right-click the small menu; X on the window quits the app — tray icon and agents gone with it.
9. Regression: model-only conversations never appear; the v0.1.1 notification click still jumps as before.

## Out of Scope (v1.0.0)

- Badges, dots, counters or color changes on the icon; a sticky panel; hide-to-tray; per-platform row configurations.
- Agent visibility with the app quit — no daemon, no headless Livebar.
- The "Hide finished agents" item in the GNOME native menu (Q20=1).
- Trash in the GNOME native menu (no hover there).
- Grouping rows by project folder.
- Time-since-finish as a separate metric.
