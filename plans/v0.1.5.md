# PRD — Klepai v0.1.5 (Theme import + light/dark toggle)

**Status:** active PRD for v0.1.5, written ahead of implementation (decided 2026-10-29 in a discovery session with the owner; pinned early "in reserve", like v0.1.2 and v0.1.4 were). Implementation order stays v0.1.0 → v0.1.1 → v0.1.2 → v0.1.3 (Brainstorm) → v0.1.4 (MCP) → v0.1.5.
**Source of truth:** `plans/prd-post-alpha.md` is the master roadmap; on conflict, the master wins. Stories 50 and 59 live in the master; this document pins down their decided details.
**Predecessor:** v0.1.4 (MCP client) ships before this version.
**Master amended by this discovery:** story 50 was reworded (input + Apply instead of "applied live"; three input forms; protective rules; reset confirms) and story 64 (light/dark toggle) was added.

---

## Problem Statement

*(carried from the master)* The app is locked to one color scheme. Klepai ships CRS-Theme — itself a tweakcn export — and nothing else: re-skinning means hand-editing CSS. And the app is dark no matter what: `<html class="dark">` is hardcoded, the light half of CRS-Theme sits dormant in `index.css`, and there is no way to prefer light.

## Solution

A Settings → **Theme** tab. The user hands Klepai a theme in any of three ways — a tweakcn share link, raw pasted CSS, or a `.css` file — and presses **Apply**. Klepai maps everything that fits onto its CSS variables (best-effort), fetches any missing font families from Google Fonts, and the app is re-skinned: live immediately, persisted across restarts, native window background included. A **light/dark toggle** in the same tab always works — it switches CRS-Theme's own two halves even with no import — and the choice persists like the theme itself. **Reset** returns to CRS-Theme after a confirmation dialog.

## User Stories

- **50** *(master, amended)* — hand Klepai a tweakcn theme (share link or raw CSS in one input, or a `.css` file), Apply maps everything that fits onto Klepai's CSS variables, the theme persists across restarts, and reset (with confirmation) returns to CRS-Theme; the KLEPAI wordmark and the semantic state colors stay fixed.
- **64** *(master, added by this discovery)* — a light/dark toggle in Settings → Theme that always works — CRS-Theme's own light and dark halves even with no import, an imported theme's two halves after one — persisted across restarts (a fresh install starts dark).

## Implementation Decisions

### The Theme tab (Q2=1, Q14=1)

- A new tab in `SettingsDialog.tsx` (the `Tab` union gains a value; the body follows the existing `*Tab` component pattern; live cross-component updates can follow the `klepai:servers-changed` event precedent).
- Working name **"Theme"** (exact label at implementation).
- Tab contents (Q17=1): **one text field** accepting either a tweakcn share link or raw pasted CSS (auto-detected: a URL is fetched, anything else is parsed as CSS), a **file picker** for `.css` beside it, and **one shared Apply button**. The **light/dark toggle** lives here too — and nowhere else (no main-window switch).

### Input forms (Q3=3)

- **Share link** — a tweakcn share URL; tweakcn is free, OSS and login-free. Exact mechanics (URL-embedded theme data vs fetching the theme page/API) and the fetching layer (Rust HTTP vs frontend fetch — CORS points to Rust) are implementation decisions.
- **Pasted CSS** — raw CSS text in the same field, parsed for custom-property declarations.
- **`.css` file** — picked from disk, parsed like pasted CSS.

### Apply flow (Q4, Q5, Q7, Q9, Q19)

- **Nothing happens until Apply** (Q4) — pasting or choosing a file does not touch the look. Apply parses, maps, applies **and persists** in one step. *(The master's original "applied live" is superseded by this decision.)*
- **Mapping is best-effort** (master boundary): every custom property whose name matches one of Klepai's CSS variables is applied; unknown tokens are silently skipped. Light and dark values of a token each import to their own variant.
- **`--spacing` is never imported** (Q11=1) — Klepai's `0.22rem` rescales the entire spacing scale; an imported value could break layout. The only protected token.
- **Fonts follow the theme** (Q12=1, Q21=2): imported font-family tokens apply; if the family is not available locally, Klepai fetches it from **Google Fonts** and caches it locally (offline keeps working after the first fetch); a failed fetch falls back silently to the existing stack — colors apply regardless. *(The app already loads ABeeZee from Google Fonts; the bundled Audiowide stays.)*
- **Success is silent** (Q7=1) — no toast, no applied-token summary.
- **Errors are inline** (Q9=1, Q19=1) — next to the field, current look unchanged: unreachable link, unparseable link content, invalid CSS, and **CSS mapping zero tokens** ("no matching tokens found" — a silent no-op would read as a broken button).

### Theme model (Q5, Q6, Q8, Q18)

- **One custom theme active globally**; the next Apply overwrites it (Q5=1). No library, no history.
- **The KLEPAI wordmark is pinned** (Q18=1, scoped to the logo only): the Audiowide wordmark in the sidebar, on the start screen and in About keeps its font **and color** — a theme and the mode toggle never touch it. It is a distinct brand face bundled locally; the pin is an explicit rule, not an accident.
- **Semantic state colors are fixed** (Q6 = NIE): needs-input blue (v0.1.1), Unrestricted red (v0.1.2), MCP error red (v0.1.4) are app constants **outside the import map** — a theme cannot re-skin them, in either mode. Standard tokens like `--destructive` map normally; only the feature-state colors added by v0.1.1–v0.1.4 are protected.
- **Reset**: a **confirmation dialog** first ("the theme will be lost") (Q8=2) — *(the master's original "one click" is superseded)* — then the custom theme is discarded and CRS-Theme is restored exactly, both halves.

### Light/dark toggle (story 64; Q10=3, Q14–Q16, Q22)

- Lives **only in the Theme tab** (Q14=1).
- **Always functional** (Q15=1): with no import it switches CRS-Theme's own light and dark halves — the light half already sits in `index.css` (`:root`), dormant today behind the hardcoded `<html class="dark">`; with an import it switches the imported theme's two halves.
- **Persistence** (Q16, Q22=1): theme and mode come back exactly as left before the app closed; a **fresh install starts dark + CRS-Theme** (today's behavior becomes the documented default).
- The **native window background** follows both the theme and the mode — updated on Apply, on toggle, and at startup (Q13=1). Startup flash guard: today's static inline `#121212` guard in `app/index.html` must honor the stored theme/mode before the first visible frame; exact mechanism at implementation.

### Boundaries

- The landing page (`index.html`) does not share the app's theme and is untouched — import and toggle are app-only.
- Theme import is fully local except the optional Google Fonts fetches for imported families.

## Assumptions

- tweakcn share links stay parseable (CSS-variable export), as CRS-Theme already proves (carried from the master).
- The settings store gains theme and mode keys (SQLite `settings` table; migration follows the existing guarded column-add pattern in `store.rs`).
- The stored theme is re-applied before the first visible frame, together with the native window background, so no flash of the wrong look occurs; the static flash guard needs a dynamic replacement (mechanism at implementation).
- Google Fonts fetches are cached locally; without network, colors still apply and text falls back to local fonts.
- Import parsing consumes custom-property declarations only — any other CSS rules in pasted or `.css` content are ignored.
- v0.1.1–v0.1.4 (needs-input blue, Unrestricted red, MCP red dots) ship before v0.1.5 and keep their state colors as constants; if any of them ends up tokenized, the import map skips those names.
- v0.1.5 scope stays exactly: story 50 + story 64 — nothing rides along (Q1=1, with the Q10=3 extension confirmed in-session).

## Tradeoffs Considered

- **Live preview while pasting** — rejected by the owner: an explicit input + Apply keeps the trigger deliberate (Q4; master's "applied live" reworded).
- **Theme library / history** — rejected as premature: one active theme + reset covers the want (Q5=1).
- **Importing `--spacing`** — rejected: a single rescaled value can stretch the entire layout; protected unconditionally (Q11=1).
- **Names-only fonts (no fetch)** — rejected: imported themes would often silently fall back and look wrong out of the box; the owner chose Google Fonts fetching with local caching (Q21=2).
- **Pinning only the wordmark font, letting color follow** — rejected: the owner pinned font and color both (Q18=1).
- **Reset without confirmation** — rejected: master said one click, the owner chose a confirm guard (Q8=2; master reworded).
- **Toggle in the main window** — rejected: one home, the Theme tab (Q14=1).
- **Toggle inactive without an import** — rejected: CRS-Theme's light half already exists; the toggle is always real (Q15=1).
- **Semantic colors overridable by theme** — rejected: "red means warning" must survive re-skinning (Q6 = NIE).
- **Leaving the native window background at `#121212`** — rejected: mismatched window edges on other backgrounds; the native bg follows theme and mode (Q13=1).

## Validation Strategy (HITL)

1. Open Settings → Theme: the tab shows the input, the file picker, Apply, the light/dark toggle, and Reset.
2. Paste a tweakcn share link → nothing changes until **Apply**; after Apply the app is re-skinned; success shows no message.
3. Paste the same theme as raw CSS (tweakcn's CSS export) → Apply gives the same result. Import a `.css` file from disk → same.
4. Paste CSS with zero matching tokens → an inline error appears; the look is unchanged.
5. Break the link (wrong URL / offline) → an inline error; the look is unchanged.
6. A theme carrying a font not installed locally: after Apply the font appears (fetched from Google Fonts); go offline and restart → the theme still renders with that font (cached).
7. Restart the app → theme and mode come back exactly as left; the native window background matches the look from the first frame.
8. Toggle light/dark **without any import** → CRS-Theme's light and dark halves switch; restart keeps the choice; a fresh-install profile (no stored state) starts dark.
9. Toggle light/dark **after an import** → the imported theme's two halves switch.
10. Reset → confirmation dialog appears; cancel keeps the theme; confirm restores CRS-Theme exactly (both halves) and clears the stored theme.
11. Check the fixed elements after an import and a mode switch: the KLEPAI wordmark (sidebar, start screen, About) renders identically; needs-input blue / Unrestricted red / MCP red dots keep their colors (against the versions that ship them).
12. The landing (`klepai.pages.dev`) is unaffected throughout.

## Out of Scope (v0.1.5)

- Theme library, history, named themes; per-conversation themes.
- Live preview before Apply; a success toast or applied-token summary.
- A main-window (non-Settings) light/dark switch; following the OS preference automatically.
- Importing `--spacing`; overriding the wordmark or the semantic state colors; overriding non-token hardcoded accents (highlight-pulse, search marker, loader grays — they stay as coded).
- Landing-page theming.
- Everything in the master's Out of Scope for the beta line.
