# PRD — Klepai Alpha v0.0.2 (Agent collision guard)

**Status:** active PRD for Alpha v0.0.2 (decided 2026-10-27 in a discovery session with the owner).
**Source of truth:** `plans/prd-post-alpha.md` is the master roadmap; on conflict, the master wins. This PRD details the v0.0.2 patch, which ships **before** the beta line starts at v0.1.0.
**Origin:** external feedback on X (a reply to the umux skills post): *"How are you handling working tree collisions when both agents write concurrently, or is execution strictly turn-based?"* Klepai runs on the same model as umux, so the same gap applies. This is a **preventive fix** — the collision was never reproduced locally; the guard closes the gap before beta.

---

## Problem Statement

Klepai lets the user run several coding agents — the built-in agent and spawned CLI agents (Claude Code, Codex, …). Nothing prevents two of them from working in the same project folder at the same time. They can silently overwrite each other's edits: neither the user nor the agents know the other one is there.

## Solution

Before an agent starts, Klepai checks whether another **Klepai-launched** agent is already working in that folder or any of its subfolders. If so, a warning dialog appears and the user decides: run anyway, run isolated in a git worktree (git folders only), or cancel. Worktree runs get a full lifecycle: their own branch, auto-committed work, click-to-merge, abort-on-conflict.

## User Stories

*(master numbering continues at 53; these stories live here, not in the master)*

- **53.** As the user, when I start an agent conversation in a folder where another Klepai-launched agent (built-in or CLI) is already working — the same folder **or a subfolder of it** — I want a warning dialog naming the running conversation, so that a collision becomes a conscious decision instead of a surprise.
- **54.** As the user, in that warning I want three choices — **Run anyway**, **Run in worktree**, **Cancel** — where "Run in worktree" appears **only when the folder is a git repository**, so that I can isolate the second agent safely or accept the risk explicitly.
- **55.** As the user, when an agent finishes its work in a worktree, I want **[Merge into project] / [Keep branch]**, so that I bring the results home with one click or defer the decision. Klepai auto-commits the agent's changes on the worktree branch first — the commits happen in the copy; the main history and branches are never touched. If the merge hits conflicts, it **aborts**: the branch stays untouched and Klepai shows the commands to merge by hand.

## Implementation Decisions

- **Detection (53)** — Klepai's own registry of running agents (built-in + spawned CLIs), keyed by project path. Collision = same absolute path **or a path inside it** (subfolders count). Agents launched outside Klepai (e.g. a terminal Claude Code) are **invisible by design** — no lockfile sniffing; only Klepai's own launches are tracked (Q21).
- **Dialog (54)** — advisory, never a hard block: "Run anyway" is always available. The copy names the colliding conversation. Worktree button visibility = git detection on the target folder.
- **Worktree (54)** — created as a sibling copy of the project (`../<project>-klepai-<slug>`, exact naming final at implementation) on its own branch. The conversation's file operations run against the worktree path; the UI still refers to the project by its original name.
- **Merge-back (55)** — on agent finish: **auto-commit all changes on the worktree branch** (explicit owner requirement, decided 2026-10-27 — this must be stated in user-facing docs), then prompt **[Merge into project] / [Keep branch]**. Merge = merge into the main checkout's current branch. On conflict: `git merge --abort`, branch and worktree preserved, message with the manual merge commands. After a successful merge the worktree and branch are cleaned up.
- **No-git folders** — warning only (Run anyway / Cancel); no isolation option. Temp-copy isolation without git was rejected: without git there is no reliable merge-back (Q15/Q20).
- **No in-run indicator** — while two agents share a folder after "Run anyway", v0.0.2 shows no extra UI marker (default accepted in discovery; revisit if it bites).

## Assumptions

- The bug is preventive: based on external feedback, not a locally reproduced failure.
- "Running agent" = a Klepai conversation whose agent is active; finished/idle conversations do not trigger the warning.
- Auto-commit on the worktree branch is acceptable to the owner and must be explicitly documented in the feature.
- The beta line is untouched: v0.0.2 contains only this guard and ships before v0.1.0.

## Validation Strategy (HITL)

1. Start an agent conversation on a project folder; while it runs, start a second one on the **same** folder → the warning dialog appears with all three buttons (worktree button visible when the folder has git).
2. Pick **Run anyway** → both agents run; no further prompts appear.
3. Pick **Run in worktree** (git project) → the second agent's edits land in the sibling copy, the main folder stays untouched while it works; on finish the merge prompt appears; **Merge into project** brings the changes into the main folder and cleans the worktree up.
4. Create a conflicting edit in the main folder, then merge → the merge aborts, branch and worktree survive, the message shows manual commands; merging by hand in the terminal succeeds.
5. Repeat step 1 in a **non-git** folder → the dialog shows only Run anyway / Cancel.
6. Start a second agent in a **subfolder** of the first agent's project → the warning still fires.
7. An agent launched outside Klepai (in a terminal) does **not** trigger the warning — expected behaviour.

## Out of Scope (v0.0.2)

- File-level claims/advisory locks — rejected for now; the folder-level warning + worktree covers the feedback.
- Turn-based queueing of agents on one folder.
- Detection of agents launched outside Klepai.
- Temp-dir isolation for non-git folders (no reliable merge-back).
- Anything else — this release is the guard only.
