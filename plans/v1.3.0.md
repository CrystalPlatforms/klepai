---

## Problem Statement

The built-in agent edits the real project folder directly: `write_file` lands immediately and `run_command` executes on the real system with no confinement. The only protection is Klepai's allow dialogs — and none at all in Unrestricted. A user who wants to let the agent attempt a bigger change hands over the project itself; and in a **non-git folder** there is no isolation at all (the v0.0.2 worktree requires git). The owner's fear covers everything at once: accidents (`rm -rf`), a malicious or mistaken model, network reach, and the trust gap that stops adoption.

## Solution

**Klepai Sandbox** — clone-based isolation. Enabling it (a per-conversation **Details setting**, default off) clones the project into the global **`~/.klepai/sandboxes/<project>/<conversation>/`** — everything except `.git` and `.klepai`, `node_modules` included — using filesystem-level cloning where available (APFS clonefile on macOS, reflink on btrfs/XFS Linux) and a plain copy elsewhere. The built-in agent's file tools re-root to the clone; `run_command` runs with cwd in the clone. A **path guard** scans every command and asks before anything reaching outside the clone. When the agent finishes, the worktree-style prompt **[Merge into project] / [Keep in sandbox]** appears; merge compares clone vs project and copies changed files back, resolving collisions **per file** via hash comparison with an ask per colliding file. A **"Sandbox" badge in the composer** shows the state; merge + close or conversation deletion removes the clone.

The agent keeps its flow — Sandbox confines the *workspace*, not the *dialog count*. Unrestricted stays untouched and the two combine: an unrestricted agent working inside a clone.

## Discovery Decisions (owner-confirmed, 2026-11-15)

### Scope and slot (Q1, Q2, Q7, Q8)

- Sandbox covers **both** the built-in agent and CLI agents — split into stages: **Stage 1** (this PRD) = built-in agent; **Stage 2** (later) = Claude Code / Codex sandbox support at spawn; **Stage 3** (later, unscheduled) = OS-level cage (Seatbelt/Landlock/AppContainer) + network control.
- Slot **v1.3.0** — Diff keeps v1.2.0; discovery pinned in reserve.
- Sandbox is a **per-conversation setting in Details — not a fourth mode** (Q7).

### The clone (Q5, Q13, Q14, Q24, Q28)

- **Global folder, not per-project:** `~/.klepai/sandboxes/` in the user's home directory, created at first install or update (exact trigger — install/start/lazy — at `/blueprint`). No `.klepai` folder inside projects → git projects see nothing.
- **One clone per conversation** (Q28): `~/.klepai/sandboxes/<project>/<conversation-id>/` (naming/sanitization exact at implementation).
- **Cloned content:** everything except `.git` and `.klepai` — `node_modules` included, so tests and builds run in the clone immediately (approved with the Q13 recommendation, Q24).
- **Creation:** filesystem-level cloning — APFS clonefile (macOS), reflink (btrfs/XFS Linux), plain-copy fallback (Windows, ext4). Copy-on-write keeps the instant, near-zero-disk promise.

### Merge-back (Q15, Q16, Q17, Q25)

- **No `.git` in the clone** — the agent never commits there (Q15).
- Machinery: **clone-vs-project file comparison + copy-back of changed files** (Q25=1) — not a git merge; the Diff machinery composes.
- **UX mirrors v0.0.2 worktree** (Q16): agent finishes → **[Merge into project] / [Keep in sandbox]**.
- Collisions (the user edited the project meanwhile): **per-file hash comparison, ask per colliding file** (Q17=2; the Diff story-83 pattern).

### Escape guard and network (Q6, Q26, Q27)

- `run_command` is **scanned**; a command pointing at paths outside the clone raises an **ask before it runs** (Q26=1, implementing the series-1 Q6=2 decision). Best-effort, string-level — accepted as such.
- **Network is free in v1**, documented honestly (Q27=1); network control joins the OS cage at stage 3.

### UX and lifecycle (Q11, Q20–Q23)

- Details setting, **default off**; new conversations start without it (Q23=1).
- A **"Sandbox" badge in the composer input** while active (Q22).
- **Independent from Unrestricted** (Q4, Q20): Unrestricted is a mode, Sandbox a setting — both can be on (agent runs without prompts, inside the clone).
- Lifecycle (Q21=1): **merge + closing the sandbox removes the clone**; **deleting the conversation removes its clone**.

### Threat model and honesty (Q10, Q12)

- The feature is a **guardrail against accidents — not a hard security boundary** (Q10=1); user-facing docs state this.
- Local-first: no cloud sandbox backends (Q12).

## Draft stories (87–92, finalized at `/blueprint`)

- **87.** *(draft)* As the user, I want a **Sandbox setting on the conversation** (Details, default off) with a **"Sandbox" badge in the composer** while it is active, so that isolation is opt-in per conversation and always visible.
- **88.** *(draft)* As the user, I want enabling Sandbox to **clone the project** into `~/.klepai/sandboxes/<project>/<conversation>/` — everything except `.git` and `.klepai`, `node_modules` included — via filesystem-level cloning (clonefile/reflink) with a plain-copy fallback, so the copy is instant and cheap where the OS allows it.
- **89.** *(draft)* As the user, I want the built-in agent to **work inside the clone** — file tools re-rooted to it, `run_command` with cwd in it — so the real project stays untouched while the agent works.
- **90.** *(draft)* As the user, I want a **path guard on `run_command`** — a command reaching outside the clone asks me before it runs — so shell-level escapes become conscious decisions.
- **91.** *(draft)* As the user, I want the worktree-style **[Merge into project] / [Keep in sandbox]** prompt when the agent finishes, with clone-vs-project file comparison, copy-back of changed files and **per-file hash conflict asks**, so bringing work home is one click and my manual edits are never silently overwritten.
- **92.** *(draft)* As the user, I want the clone **cleaned up for me** — removed on merge + close and on conversation deletion — so sandboxes never pile up on disk.

## Open questions (for `/blueprint`)

- **Merge review:** does the merge prompt ride the Diff view (v1.2 composition) — review the clone's changes before applying?
- **Diff interplay:** while sandboxed, what does the Agent changes tab show (clone-rooted snapshots)? Does it recompute after merge-back touches the real project?
- **Collision dialog:** should the v0.0.2 dialog gain **"Run in sandbox"** as the isolation option for non-git folders (worktree is git-only; sandbox is not)?
- **Orphan clones:** a crash leaves a clone whose conversation row is gone — startup sweep or lazy cleanup?
- **Folder creation timing:** first install/update (owner's words) vs lazily on first sandbox use vs at app start.
- **Read scope:** file tools see only the clone (a full copy) — confirm no read-through to the original project is wanted.
- **Git-less confusion:** the agent may run `git` commands inside the clone (no repo there) — accept the errors or inform the model once?
- **Badge polish:** clickable (opens Details) or static?
